|浏览量:

传输层提供的服务

传输层属于面向通信部分的最高层，同时也是用户功能中的最低层。
传输层的主要功能如下：

  • 应用进程之间的逻辑通信
    应用进程之间的通信也称端到端通信。从传输层来看，通信的真正端点不是主机而是主机中的进程。
  • 复用和分用
    复用是指发送方不同的应用进程都可以使用同一个传输层协议传送数据。
    分用是指接受方的传输层在剥去报文的首部后能够把这些数据正确交付到目的应用进程。
  • 差错检测
    对于YCP，若接收方发现报文段出错，则要求发送方重发该报文段。对于UDP，若接收方发现数据报出错，则直接丢弃。
  • 提供面向连接和无连接的传输协议

1.传输层的寻址与端口

端口能让应用层的各种进程将其数据通过端口向下交付给传输层，以及让传输层知道应当将其报文段中的数据向上通过端口交付给应用层相应的进程。
硬件端口是不同硬件设备进行交互的接口，软件端口是应用层的各种协议进程与传输实体进行层间交互的一种地址。
传输层使用的是软件接口。

端口号只具有本地意义，根据端口号范围可将端口分为两类：

  • 服务器使用的端口号：分为两类，最重要的一类是熟知端口号，数值为0-1023，IANA（互联网地址指派机构）把这些端口号指派给了TCP/IP最重要的一些应用程序。另一类成为登记端口号，数值为1024-49151，它是供没有熟知端口号的应用程序使用的，使用这类端口号必须在IANA登记。
    FTP 21; TELVET 23; SMTP 25; DNS 53; TFTP 69;HTTP 80;SNMP 161。
  • 客户端使用的端口号：数值为49152-65535。因为这类端口号仅在客户进程运行时才动态选择，所有也称短暂端口号。

2.无连接服务和面向连接服务

TCP/IP族在IP层之上使用了两个传输协议：一个是面向连接的传输控制协议（TCP），；另一个是无连接的用户数据报协议（UDP）。

TCP提供面向连接的可靠服务，不提供广播或多播服务。主要适用于可靠性更重要的场合，如文件传输协议（FTP）、超文本传输协议（HTTP）、远程登录（TELVET）等。

UDP提供无连接的不可靠服务。UPD在IP层之上仅提供两个附加服务：多路复用和对数据的错误检查。使用UDP的应用主要包括小文件传送协议（TFTP）、DNS、SNMP和实时传输协议（RTP）。

一些典型互联网应用锁用的TCP/IP应用层协议和传输层协议如下：

互联网应用 TCP/IP 应用层协议 TCP/IP 传输层协议
域名解析 域名系统（DNS） UDP
文件传送 简单文件传送协议（TFTP） UDP
路由选择 路由信息协议（RIP） UDP
IP 地址分配 动态主机配置协议（DHCP） UDP
网络管理 简单网络管理协议（SNMP） UDP
电子邮件 简单邮件传送协议（SMTP） TCP
远程终端接入 远程终端协议（TELNET） TCP
万维网 超文本传送协议（HTTP） TCP
文件传送 文件传送协议（FTP） TCP

UDP

UDP仅在IP层的数据报服务之上增加了复用、分用和差错检测的功能。
UDP的特点：

  • UDP无须建立连接。
  • 无连接状态。
  • UDP的首部开销小。
  • UDP没有拥塞控制。
  • UDP支持一对一、一对多、多对一和多对多的交互通信。

UDP常用于一次性传输较少数据的网络应用。
UDP是面向报文的，报文不可分割，是UDP数据报处理的最小单位。

1.UDP的首部格式

  • 源端口。在需要对方回信时选用，不需要时可用全0。
  • 目的端口。这在终点交付报文时必须使用到。
  • 长度。UDP数据报的长度，最小值是8。
  • 校验和。检验UDP数据报在传输中是否有错。有错就丢弃。

当传输层从IP层收到UDP数据报时，就根据首部中的目的端口，把UDP数据报通过相应的端口，上交最后的终点——应用进程
若接收方UDP发现收到的报文中的目的端口号不正确，则就丢弃该报文，并由ICMP发送“端口不可达”差错报文给发送方。

2.UDP检验

UDP计算检验和的方法和计算IP数据报首部检验和的方法基本相同。不同的是：IP数据报的校验和只检验IP数据报的首部，但UDP的校验和要将首部和数据部分一起检验。
UDP计算校验和的方法：在发送方，先把全0放入校验和阻断，再把伪首部和UDP数据报看成是由许多16位的字串接起来的。若UDP数据报的数据部分不是偶数个字节，则要在末尾填入一个全0字节（但此字节不发送）。然后按二进制反码计算出这些16位字的和。将此和的二进制反码写入检验和字段，并发送。在接收方，把收到的UDP数据报连同伪首部（若不是偶数个数字节，则还需补上一个全0字节）后，按二进制反码求这些16位字的和。当无差错时其结果应该全1，否则就表明有差错出现，接收方就应丢弃这个UDP数据报。

3.TCP

TCP是在不可靠的IP层之上实现的可靠的数据传输协议。
主要特点有：

  • TCP是面向连接的传输层协议，TCP连接是一条逻辑连接。
  • 每一条TCP连接只能有两个断点，每一条TCP连接只能是一对一的。
  • TCP提供可靠交付的服务，保证传送的数据无差错、不丢失、不重复且有序。
  • TCP提供全双工 通信。
  • TCP是面向字节流的。

TCP和UDP在发送报文时所采用的方式完全不同。UDP报文的长度由发送应用进程决定，而TCP报文的长度则根据接收方给出的窗口值和当前网络拥塞程度来决定。

1.TCP报文段

TCP传送的数据单元称为报文段。TCP报文段既可用来运载数据，又可用来建立连接、释放连接和应答，一个TCP报文段分为首部和数据两部分，整个TCP报文段作为IP数据报的数据部分封装在IP数据报中。

  • 序号：占4B。范围是0 - $2^{32}-1$。TCP连接中传送的字节流中的每个字节都要按顺序编号，序号字段值指的是本报文段所发送的数据的第一个字节的序号。
  • 确定号：占4B。是期望收到对方下一个报文段的第一个数据字节的序号。
  • 数据偏移（首部长度）：占4位，它指出TCP报文段的数据起始处距离TCP报文段的起始处有多远。
  • 保留：占6位，目前应置为0。
  • 紧急位URG：当URG=1时，表明紧急指针字段有效。它告诉系统此报文段中有紧急数据，应尽快传送。紧急数据被插入至报文段的最前面，而在紧急数据后面的数据仍是普通数据，因此要与首部中的紧急指针字段配合使用。
  • 确定位ACK：仅当ACK=1时确定号字段才有效。当ACK=0时，确定号无效。
  • 推送位PSH（Push）：两个应用进程进行交互式通信时，都希望在键入一个命令后立即就能收到对方的响应，此时发送方TCP将PSH置为1，接收方TCP收到PSH=1的报文段后，就尽快交付给接收应用进程，而不在等到整个缓存都填满了后再向上交付。
  • 同步位SYN：到SYN=1时表示这是一个链接请求或连接接受报文。
  • 终止位FIN：用来释放一个链接。当FIM=1时，表明此报文段的发送方的数据已发送完毕，并要求释放传输裂解。
  • 窗口：占2B，窗口值告诉对方，从本报文段首部中的确定号算起，接收方目前允许对方发送的数据量（以字节为单位）。
  • 校验和：占2B，校验和字段校验的范围包括首部和数据两部分。计算校验和时，和UDP一样，要在TCP报文段的前面加上12B的维首部。
  • 紧急指针：占2B，仅在URG=1时才有意义，它指出报文段中的紧急数据的字节数。即使窗口为零，也可以发送紧急数据。
  • 选项：长度可变，最长可达40B。
  • 填充：这是为了使整个首部长度是4B的整数倍。

2.TCP连接管理

TCP连接的端口即为套接字，每一条TCP连接唯一地被通信的两个端口（两个套接字）所确定。同一个IP地址可以有多个不同的TCP连接，而同一个端口号也可以出现在多个不同的TCP连接中。
TCP连接的建立采用客户/服务器模式。

TCP连接的建立
经历以下三个步骤，通常称为三次握手：

建立连接前，服务器处于LISTEN（收听）状态，等待客户的连接请求。

  • 第一步：客户向服务器发送连接请求报文段。该报文段的 SYN = 1，同时选择一个初始序号 seq = x。TCP 规定，SYN 报文段（SYN=1 的报文段）不能携带数据，但仍消耗一个序号，因此客户下一次发送的报文段序号 seq = x + 1。此时，客户进入 SYN-SENT（同步已发送）状态。
  • 第二步：服务器收到连接请求后，若同意建立连接，则向客户返回确认报文段。该报文段的 SYN = 1、ACK = 1，确认序号 ack = x + 1，同时选择自己的初始序号 seq = y。确认报文段同样不能携带数据，但也消耗一个序号。此时，服务器进入 SYN-RCVD（同步已收到）状态。
  • 第三步：客户收到确认后，再向服务器发送最终确认。该确认报文段的 ACK = 1，确认序号 ack = y + 1，序号 seq = x + 1。此报文段可以携带数据。若不携带数据，则不消耗序号，下一个数据报文段的序号仍为 x + 1。此时，客户进入 ESTABLISHED（已建立连接）状态。

当服务器收到来自客户机的确定后，也进入ESTABLISHED状态。

TCP连接的释放
TCP连接释放的过程通常称为四次挥手：

  • 第一步：客户决定关闭连接时，向服务器发送连接释放报文段，并停止发送数据（主动关闭）。
    该报文段的 FIN = 1，序号 seq = u，其值等于此前已发送数据的最后一个字节序号加 1。TCP 规定，FIN 报文段（FIN = 1 的报文段）即使不携带数据，也消耗一个序号。此时，客户进入 FIN-WAIT-1（终止等待 1）状态。由于 TCP 是全双工的，可视为连接包含两条独立的数据通路；发送 FIN 的一端关闭了其发送方向，但对方仍可继续发送数据。
  • 第二步：服务器收到连接释放报文段后，立即发送确认报文段。该报文段的 ACK = 1，确认序号 ack = u + 1，序号 seq = v（v 为服务器此前已发送数据的最后一个字节序号加 1）。随后，服务器进入 CLOSE-WAIT（关闭等待）状态。此时，从客户到服务器方向的连接已释放，但从服务器到客户方向的连接并未释放，TCP 连接处于半关闭状态。客户收到确认后，进入 FIN-WAIT-2（终止等待 2）状态，等待服务器发出的连接释放报文段。
  • 第三步：若服务器已经没有要向客户发送的数据，就向其发送连接释放报文段。该报文段的 FIN = 1、ACK = 1，序号 seq = w（w 可能大于 v，因服务器在半关闭期间可能又发送了数据），还需重复此前已发送的确认序号 ack = u + 1。此时，服务器进入 LAST-ACK（最后确认）状态。
  • 第四步：客户收到连接释放报文段后，必须发送最终确认，并进入 TIME-WAIT（时间等待）状态。该确认报文段的 ACK = 1，确认序号 ack = w + 1，序号 seq = u + 1。服务器收到此确认后，即进入 CLOSED（连接关闭）状态。客户在 TIME-WAIT 状态下，还需等待时间等待计时器设置的时间 2MSL（Maximum Segment Lifetime，最长报文段寿命）后，才进入 CLOSED 状态。

对上述TCP连接的建立和释放的总结如下：
1）建立连接分为3步：

  • SYN=1，seq=x
  • SYN=1，ACK=1，seq=y，ack=x+1
  • ACK=1，seq=x+1，ack=y+1

2）释放过程分为4步：

  • FIN=1，seq=u
  • ACK=1，seq=v，ack=u+1
  • FIN=1，ACK=1，seq=w，ack=u+1
  • ACK=1，seq=u+1，ack=w+1

3.TCP可靠传输

TCP在不可靠的IP层之上建立一种可靠数据传输服务。
序号
TCP首部的序号字段用来保证数据能有序提交给应用层，序号建立在传输的字节流之上，而步建立在报文段之上。

确定
TCP首部的确定号是期望收到对方的下一个报文段的数据的第一个字节的序号。
TCP默认使用累加确定，即TCP只确定数据流中第一个丢失字节为止的字节，这样可以减少传输开销。

重传
有两种事件会导致TCP对报文段进行重传：超时和冗余ACK
（1）超时
TCP每次发送一个报文段，就对这个报文段设置一个超时计时器。计时器设置的重传时间到期但未收到确认时，就要重传这一报文段。
TCP采用一种自适用算法，它记录一个报文段发出的时间，以及收到相应确定的时间，这两个时间之差称为报文段的往返时间（RTT）。TCP维护了RTT的一个加权平均往返时间RTTS，它会随新测量RTT样本值的变化而变化。超时计数器设置的**超时重传时间（RTO）**应略大于RTTS，但也不能大太多，否则当报文段丢失时，TCP不能很快重传，导致数据传输时延大。

（2）冗余ACK（冗余确定）
发送方通常可在超时事件发生之前通过注意所谓的冗余ACK来较好地检测丢包情况。冗余ACK就是再次确定某个报文段ACK，而发送方先前已经收到该报文段的确定。这种技术通常称为快速重传。

4.TCP流量控制

流量控制的功能就是让发送方的发送速率不要太快，以便让接收方来得及接收。
TCP利用滑动窗口机制来实现流量控制。
发送方的发送窗口不能超过接收方给出的接收窗口值，以限制发送方向网络注入报文的速率。
利用接收滑动窗口实现流量控制的过程

TCP为每个连接设有一个持续计时器，只要发送方收到对方的零窗口通知，就启动持续计时器。若计时器超时，就发送一个零窗口探测报文段，而对方就在确定这个探测报文段时给出现在的窗口值。若窗口仍然为零，则发送方收到确定报文段后就重新设置接收计时器。

传输层和数据链路层的流量控制的区别是：传输层实现的是端到端，即两个进程之间的流量控制；数据链路层实现的是两个中间的相邻节点之间的流量控制。此外，数据链路层的滑动窗口协议的窗口大小不能动态变化，传输层的窗口大小则可以动态变化。

5.TCP拥塞控制

拥塞控制是指防止过多的数据注入网络，保证网络中的路由器或链路不致过载。
TCP进行拥塞控制的算法有四种：慢开始、拥塞避免、快重传和快恢复。
发送方控制拥塞窗口的原则：只要网络未出现用三个，拥塞窗口就再增大一些，以便把更多的分组发送出去，以提高网络的利用率。但只要网络出现拥塞，拥塞窗口就减少一些，以减少注入网络的分组数，以缓解网络出现的拥塞。

发送窗口的上限值应取接收窗口rwnd和拥塞窗口cwnd中较小的一个。
注：下面采用最大报文段长度MSS作为拥塞窗口大小的单位。
慢开始和拥塞避免
慢开始算法：思路是当发送方刚开始发送数据时，因为并不清楚网络的负荷情况，若立即把大量数据注入网络，则有可能引发网络拥塞。具体方法是：先发送少量数据探测一下，若没有发送拥塞，则适当增大拥塞窗口，即由小到大逐渐增大拥塞窗口（发送窗口）。
拥塞避免算法：思路是让拥塞窗口cwnd缓慢增大，具体做法是：每经过一个往返时延RTT就把发送方的拥塞窗口加1，而不是加倍，使拥塞窗口cwnd按线性规律换吗增长（加法增大）。
根据cwnd的大小执行不同的算法，可归纳如下：

  • 当cwnd < ssthresh时，使用慢开始算法。
  • 当cwnd > ssthresh时，停止使用慢开始算法，而改用拥塞避免算法。
  • 当cwnd = ssthresh时，既可使用慢开始算法，也可使用拥塞避免算法（常规做法）。

网络拥塞的处理：首先把慢开始门限ssthresh设置为出现拥塞时的发送方的cwnd值的一半（但不能小于2），然后把拥塞窗口cwnd重新设置为1，执行慢开始算法。

慢开始和拥塞避免算法的实现过程：

  • 起初时，拥塞窗口置为1，即cwnd-1，慢开始门限置为16，即ssthresh=16。
  • 慢开始阶段，发送方每收到一个队新报文的确定ACK，就把拥塞窗口cwnd值加1，也即经过每个传输轮次（RTT），cwnd呈指数规律增长。当cwnd增长到慢开始门限ssthresh时，就改用拥塞避免算法，cwnd按线性规律增长。
  • 当cwnd=24时，网络出现超时，调整ssthresh值为12（超时时cwnd值的一半），同时cwnd置为1，并执行慢开始算法；当cwnd=12时，改为执行拥塞避免算法。

快重传和快恢复
快重传算法：是使发送方尽快进行重传，而不等超时计时器超时再重传。
快恢复算法：当发送方连续收到3个冗余ACK（重复确定）时，执行乘法减小方法，把慢开始门限ssthresh调整为当前cwnd的一半。

在TCP连接建立和网络出现超时时，采用慢开始和拥塞控制避免算法（ssthresh=cwnd/2，cwnd=1）；当发送方收到3个冗余ACK时，采用快重传和快恢复算法（ssthresh=cwnd/2，cwnd-ssthresh）。

发送方发送窗口的大小由流量控制和拥塞控制共同决定。
发送方发生窗口的实际大小是由rwnd和cwnd中较小的一个确定的。
